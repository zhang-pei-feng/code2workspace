# 本地数据库检索型

## 任务形状

问题依赖本地数据库、快照、导出表或仓库内查询脚本，例如：
“某个毒株位点的风险评分是什么？”

## 规划难点

- 容易误把“数据库查询题”当成“联网检索题”
- 容易先给概念性总结，而不是先拿本地证据

## 应先看什么证据

- 本地数据库 schema、查询脚本、表字段说明
- 已有 snapshot、导出结果、测试样例
- 仓库中能直接证明字段含义和评分口径的代码或文档

## 推荐执行顺序

1. 先确认问题要的是位点、突变、风险等级还是统计汇总。
2. 找到本地真实数据入口，再决定是直接 SQL、脚本还是已有快照。
3. 先返回可验证的原始结果，再做一小段机制解释。

## 验证方式

- 结果里要能对上具体字段、表名、查询条件或输出文件
- 不要只给“常识性解释”而没有本地证据

## 常见误规划

- 一看到变异/抗体就先上网
- 先写机制分析，最后才想起没有本地数据支撑
