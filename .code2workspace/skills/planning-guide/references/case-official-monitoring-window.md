# 官方监测时效型

## 任务形状

问题依赖最近 7 天、14 天、28 天或最近一个月的官方监测数据，例如：
“近 28 天全球病例数是多少？”

## 规划难点

- 时间窗口容易混淆
- “最新”常常要求官方网页或最新报告，而不是历史快照
- 不同机构口径可能不同，必须标明来源和时间范围

## 应先看什么证据

- 官方 dashboard、官方周报、官方 API 或官方数据表
- 仓库内如有缓存/快照，先确认是否还能代表当前问题

## 推荐执行顺序

1. 先锁定时间窗口和统计口径。
2. 优先找官方来源中的最新可验证数字。
3. 如果还需要国家/地区排行，再看同一来源是否给出可比口径。
4. 回答时同时给数字、时间窗口和来源说明。

## 验证方式

- 数字必须带时间窗口
- 来源必须是官方或主来源
- 如果两个来源口径不同，要明确说明而不是混算

## 常见误规划

- 用旧缓存替代最新官方数据
- 混用“近 7 天”和“近 28 天”数字
- 给结论不写来源日期
